All endpoints live under `/v0`. Bodies are JSON. Errors use a `{code, message,
details}` envelope.

## Authentication

- **Client and admin routes** use a bearer token: `Authorization: Bearer <token>`.
  Scoped keys limit permissions; `--bearer-token` / `REBUNO_BEARER_TOKEN` sets
  the full-access bootstrap token required in server mode. Tokens are
  case-sensitive. Dev mode allows anonymous access but checks supplied tokens.
- **Agent routes** use the v1 HMAC signature described below. Agents can access
  only their assigned executions (`403 forbidden` otherwise).
- **Agent routes that change durable state** also send `Rebuno-Dispatch-Id` and
  `Rebuno-Dispatch-Attempt`, copied from the webhook that delivered the run. A
  call from an attempt the kernel has already re-delivered gets
  `409 lease_superseded`.
- A few routes (fetching execution input and steps) take either one: bearer for
  clients, HMAC for the agent.
- Step routes require the step to belong to the execution in the URL. A
  mismatched execution and step returns `404 not_found`.
- `/v0/health`, `/v0/ready`, and `/metrics` are unauthenticated.

### Scopes

Scopes apply deployment-wide; write does not include read. Insufficient scope
returns `403 forbidden`; invalid or revoked keys return `401 unauthorized`.

| Scope | Access |
|-------|--------|
| `executions:read` | Read executions, steps, events, and streams. |
| `executions:write` | Create and cancel executions. |
| `approvals:read` | List and inspect approvals. |
| `approvals:write` | Grant and deny approvals. |
| `agents:read` | Read agents and their policies. |
| `agents:write` | Register, update, or delete agents. |
| `policies:write` | Set policies; testing also requires `executions:read`. |
| `api_keys:manage` | Manage keys with any scopes. |

### Request signatures

Agent requests send `Rebuno-Agent-Id`, `Rebuno-Timestamp`, and
`Rebuno-Signature: v1=<lowercase hex HMAC-SHA256(secret, message)>`, using the
agent's registered secret. Build `message` from these UTF-8 fields, separated by
LF with a trailing LF, then append the exact raw request body:

```text
rebuno-request-v1
HTTP method
escaped path and raw query (including ? when present)
Rebuno-Timestamp
Rebuno-Dispatch-Id (empty if absent)
Rebuno-Dispatch-Attempt (empty if absent)
```

`Rebuno-Timestamp` is decimal Unix seconds, within 300 seconds of the kernel's
clock. The secret binds the request to the agent named in `Rebuno-Agent-Id`.
Invalid signatures or timestamps return `401 unauthorized`. Sign the final URL on
each request; proxies must preserve its path and query. Requests can still be
repeated within the time window. Webhook signatures use `sha256=...`.

A step submission signed with the secret `test-secret`:

```http
POST /v0/executions/018f3a2b-4c5d-7e6f-8a9b-0c1d2e3f4a5b/steps
Rebuno-Agent-Id: test-agent
Rebuno-Timestamp: 1700000000
Rebuno-Dispatch-Id: 01920000-0000-7000-8000-000000000001
Rebuno-Dispatch-Attempt: 3
Content-Type: application/json

{"kind":"tool_call","target":"send_email","args":{"to":"ops@example.com"},"idempotency":"safe_to_retry"}
```

The message, with the line feeds escaped for print and the body following the
final one directly:

```text
rebuno-request-v1\nPOST\n/v0/executions/018f3a2b-4c5d-7e6f-8a9b-0c1d2e3f4a5b/steps\n1700000000\n01920000-0000-7000-8000-000000000001\n3\n{"kind":"tool_call","target":"send_email","args":{"to":"ops@example.com"},"idempotency":"safe_to_retry"}
```

That gives `Rebuno-Signature: v1=017dff4039ba40e90d3d8d566fdf51db427672f92d45ef41b738672238ea0058`.

## Client API

### Create an execution

`POST /v0/executions` · bearer

```json
{ "agent_id": "researcher", "input": { "query": "hello" } }
```

Returns `201` with the created execution. The kernel records `execution.created`
and enqueues a dispatch.

Add an optional `session` to continue a chain of executions, such as the turns
of a conversation:

```json
{
  "agent_id": "researcher",
  "session": "chat:u42:c7",
  "input": { "query": "hello" }
}
```

The execution returns `running` when the session is free and `pending` when
another execution in it is running or blocked. Add `parent_execution_id` to
continue a completed execution of the same agent. With it, `session` is
optional and, when given, must have no executions yet. Sessions are global to the
kernel, so executions for two different agents in one session also run one at a
time. See [Sessions](/architecture#sessions).

### Get an execution

`GET /v0/executions/{id}` · bearer or HMAC

```json
{
  "id": "0192...", "agent_id": "researcher", "status": "completed",
  "session": "chat:u42:c7", "parent_execution_id": "0191...",
  "input": {...}, "output": {...}, "failure_reason": "",
  "created_at": "...", "updated_at": "...", "deadline_at": null
}
```

`session` and `parent_execution_id` are present when set. Unless named at
creation, the parent is set when an execution in a session starts. A fork also
carries `forked_from` and `fork_seq`.

### Get the previous state

`GET /v0/executions/{id}/previous` · bearer or HMAC

```json
{ "state": {...} }
```

The `state` the execution's parent completed with, or the parent's `output` when
it recorded no state. `state` is `null` for an execution with no parent.

### List executions

`GET /v0/executions?agent_id=&session=&status=&cursor=&limit=` · bearer

Newest first. Keyset paging: pass the returned `next_cursor` back as `cursor`.
`session` filters by exact session.

```json
{ "executions": [ ... ], "next_cursor": "0192..." }
```

### Get the event log

`GET /v0/executions/{id}/events?after_seq=&limit=` · bearer

Returns an ordered array of [events](/events). `limit` defaults to 100, max
1000. Poll with `after_seq` set to the last `event_seq` you saw.

### Stream live output

`GET /v0/executions/{id}/stream` · bearer

Server-Sent Events carrying the deltas an agent publishes while a step is still
running. Best-effort, never persisted, and separate from the event log. See
[Live streaming](/streaming).

### Fork an execution

`POST /v0/executions/{id}/fork` · bearer

```json
{ "session": "login-fix-retry", "at_seq": 214 }
```

Returns `201` with the new execution. The fork reruns the source's input and
replays the steps it recorded up to event `at_seq`. `session` is optional and,
when given, must have no executions yet. An optional `policy_bundle`
governs the fork in place of the agent's bundle and requires `policies:write`.
See [Forks](/architecture#forks).

For registered [resources](/architecture#external-resources), `restoration`
records each resource's starting state:

```json
{
  "workspace": {
    "checkpoint_ref": "snapshot-abc",
    "checkpoint_seq": 65,
    "covered": false
  },
  "database": { "covered": false }
}
```

`checkpoint_seq` is the checkpoint's source coverage boundary. No reference
means initial state. `covered` reports whether it matches the history at
`at_seq`; uncovered points remain forkable. The map is also recorded in
`execution.forked`.

### List fork points

`GET /v0/executions/{id}/fork-points` · bearer

```json
{
  "latest_seq": 14,
  "resources": { "workspace": 5 },
  "checkpoints": [
    { "key": "workspace", "generation": 0, "checkpoint_ref": "snap-0", "covered_seq": 6, "invalidated_seq": 10 }
  ]
}
```

`resources` maps keys to registration events. Checkpoints cover
`covered_seq <= seq < invalidated_seq`, with an open end when `invalidated_seq`
is absent. A boundary is covered when all resources registered there have
coverage; with none, it is covered. Use these intervals to mark coverage on a
timeline. All boundaries remain selectable.

### Cancel an execution

`POST /v0/executions/{id}/cancel` · bearer → `204`

Records `execution.cancelled`, moves the execution to a terminal state, and stops
further dispatch. An execution that is already terminal returns `409 conflict`.

## Agent API

The kernel dispatches a webhook carrying `{execution_id, dispatch_id,
dispatch_attempt, lease_timeout_seconds}`. The agent acks `200 OK`, then pulls
what it needs and drives its effects. These routes are HMAC-verified, except the
reads, which also take a bearer token.

### Read execution input and steps

`GET /v0/executions/{id}` returns the original `input` and the current `status`.

`GET /v0/executions/{id}/steps?status=terminal` returns the execution's steps in
one read, for inspection and auditing. `status=terminal` trims the list to
`succeeded`, `failed`, and `denied`.

`GET /v0/executions/{id}/steps/{step_id}` looks up one step, and returns `404` if
it is not there.

### Submit a step

`POST /v0/executions/{id}/steps` · HMAC · dispatch headers

```json
{ "kind": "tool_call", "target": "web_search", "args": {...}, "idempotency": "safe_to_retry" }
```

Optional `resources` names registered [resources](#resources) the step may
change. Defaults to none. LLM calls affect none. Unknown keys
return `400`; the declaration does not affect step identity.

`kind` is `tool_call`, `llm_call`, or `local`. The dispatch headers are
required, and the kernel rejects the request if either is missing, or if they
name a dispatch that is not this execution's or an attempt that no longer owns
it. The dispatch scopes the kernel's occurrence counter. The kernel derives the
step ID, runs the [replay short-circuit and policy](/architecture), and
returns a decision. The `step_id` that comes back is what addresses the step's
`complete` and `fail` routes:

```json
{ "decision": "proceed", "step_id": "9a3f…" }
```

| `decision` | Meaning |
|------------|---------|
| `proceed` | New step allowed. Perform the effect, then call `complete`/`fail`. |
| `replay` | Already recorded. `result` or `error` comes back. Do not re-run the effect. |
| `denied` | Policy denied the call. `reason` says why. |
| `blocked` | Stop and exit the dispatch. The kernel re-dispatches later. `approval_id` is present when a human decision is pending. |
| `execution_blocked` | An earlier step is awaiting approval, so no new effect can start. Stop and exit the dispatch. |
| `rate_limited` | A rule's rate limit refused the call. `reason` says why. |
| `execution_terminal` | The execution is already cancelled or finished. Exit cleanly. |

A `proceed` decision includes affected resource generations and capture cadence:

```json
{ "decision": "proceed", "step_id": "9a3f…", "resources": [{ "key": "workspace", "generation": 5, "due": true }] }
```

When `due` is true, capture after the effect and report it with the outcome.

### Report a step outcome

`POST /v0/executions/{id}/steps/{step_id}/complete` takes `{ "result": {...} }`
and records `step.succeeded`.

`POST /v0/executions/{id}/steps/{step_id}/fail` takes `{ "error": {...} }` and
records `step.failed`.

Both accept captures and capture failures, committed with the outcome:

```json
{
  "result": {...},
  "captures": [{ "key": "workspace", "generation": 5, "checkpoint_ref": "snapshot-abc" }],
  "capture_failures": [{ "key": "database", "generation": 3, "error": "snapshot timed out" }]
}
```

Captures require the current generation and no other active writer. Refused
captures record `resource.checkpoint_failed`; the step outcome is preserved.

### Resources

`POST /v0/executions/{id}/resources` · HMAC · dispatch headers

Registers a resource and returns its current state:

```json
{
  "key": "workspace",
  "driver_id": "example.e2b.v1",
  "configuration": { "timeout": 600 },
  "coverage_reuse": false,
  "every_steps": 5,
  "on_completion": true
}
```

`key` matches `[A-Za-z0-9_.-]{1,128}`. Defaults: `every_steps=0` disables
checkpointing, and `coverage_reuse=false`. With a positive interval,
`on_completion` defaults to true. Registration can enable checkpointing on an
existing resource; enabled policies are preserved. Differences in `driver_id`,
`configuration`, or `coverage_reuse` return `409 conflict`. The response adds:

| Field | Meaning |
|-------|---------|
| `generation` | Current version to report with captures. |
| `count` | Settled affecting steps. |
| `registered_seq` | Registration event sequence. |
| `binding` | JSON locator for opening the resource, absent until bound. |
| `checkpoint_ref` | Fork starting checkpoint, absent for initial state. |
| `covered` | Whether the current state has checkpoint coverage. |

Session turns inherit their completed parent's registrations, policies, and
bindings. `generation` and `count` start at zero; `covered` is false until a
baseline is captured.

`POST /v0/executions/{id}/resources/{key}/binding` · HMAC · dispatch headers → `204`

Takes `{ "binding": {...} }`. A different binding for an already bound resource
returns `409 conflict`.

`POST /v0/executions/{id}/resources/checkpoints` · HMAC · dispatch headers → `204`

Takes `captures` and `capture_failures` as above, covering the latest event.

### Publish a stream delta

`POST /v0/executions/{id}/steps/{step_id}/stream` · HMAC → `204`

Body `{ "seq": <int64>, "data": "<chunk>" }`. Live output while a step runs,
delivered best-effort. `data` is opaque to the kernel and capped per batch. A
step that is no longer executing returns `409 conflict`. See
[Live streaming](/streaming).

### Send a heartbeat

`POST /v0/executions/{id}/heartbeat` · HMAC → `204`

Touches the dispatch lease so a long-running dispatch is not reclaimed as
stalled.

### Report execution outcome

`POST /v0/executions/{id}/complete` takes `{ "output": {...}, "state": {...} }` →
`204`. Records `execution.completed`. `output` goes to callers. The optional
`state` is kept for the next execution in the session, which reads it from
`previous`.

`POST /v0/executions/{id}/fail` takes `{ "error": "..." }` → `204`. Records
`execution.failed`.

## Admin API

### API keys

Require `api_keys:manage` or the bootstrap token.

| Endpoint | Result |
|----------|--------|
| `POST /v0/api-keys` | Create from `{"name":"reader","scopes":["executions:read"]}` → `201`. |
| `GET /v0/api-keys` | List metadata, including revoked keys. |
| `POST /v0/api-keys/{id}/rotate` | Replace the secret, keeping ID and scopes → `200`. |
| `DELETE /v0/api-keys/{id}` | Revoke; repeatable → `204`. |

Creation and rotation return `{id, name, scopes, created_at, token}`; save the
token, which is shown once. Rotation invalidates the old token; rotating a
revoked key returns `409 conflict`. Existing requests and streams may finish.

### Agents

`POST /v0/agents` · bearer registers or upserts an agent. Body
`{ "id", "webhook_url", "secret", "lease_timeout_seconds?" }`. Returns `201` and
the stored agent.

`GET /v0/agents` · bearer lists agents.

`GET /v0/agents/{id}` · bearer fetches one.

`DELETE /v0/agents/{id}` · bearer → `204`.

An agent reads `{ "id", "webhook_url", "policy_bundle?", "registered_at",
"lease_timeout_seconds?" }`. The secret is never returned.

### Policy

`POST /v0/policies/{agent_id}` · bearer loads or replaces the agent's bundle.
Body `{ "bundle": "<raw YAML>" }` → `204`. See [Policy](/policy).

`POST /v0/policies/{agent_id}/test` · bearer evaluates a bundle without storing
it. Body `{ "bundle?", "cases?", "execution_id?", "executions?" }`. Omit `bundle`
to test the agent's stored one; give `cases` to evaluate inputs, `execution_id`
to replay a past execution's steps, or `executions`
(`{ "session?", "since?", "limit?" }`) to replay the agent's executions newest
first, 100 by default and at most 1000. Each replayed case names its
`execution_id`. Returns each case's decision and a count of those that
did not match. See [Testing a bundle](/policy#testing-a-bundle).

### Approvals

`GET /v0/approvals` · bearer lists pending approvals.

`GET /v0/approvals/{id}` · bearer fetches one.

`POST /v0/approvals/{id}/grant` · bearer takes `{ "decided_by", "rationale?" }`
→ `204`. Resumes the execution, and the gated step proceeds.

`POST /v0/approvals/{id}/deny` · bearer takes `{ "decided_by", "rationale?" }`
→ `204`. The resumed loop sees a policy error at that step.

Both return `403 forbidden` if `decided_by` is absent from a configured
`approvers` list. The caller supplies this name; bearer credentials do not verify
human identity. See [Approvals](/policy#approvals).

## Operational endpoints

`GET /v0/health` is a liveness check, returning `{"status":"ok"}`.

`GET /v0/ready` is a readiness check, returning `503` if a dependency check
fails.

`GET /metrics` serves Prometheus metrics.
