The dashboard is a Next.js app that reads and drives a running kernel over the
[HTTP API](/api). It lives in its own repository,
[rebuno/dashboard](https://github.com/rebuno/dashboard).


<img src="/assets/execution.gif"/>


## Pages

| Page | What it does |
|------|--------------|
| Executions | Lists executions and opens one to show its event log and steps side by side, or its session and subagent tree. Creates a new execution against any registered agent, or cancels a running one. |
| Agents | Lists registered agents, registers a new one, deletes one, and edits its policy bundle. |
| Approvals | Lists approvals still pending, soonest timeout first, and grants or denies each one. |
| Metrics | Kernel counters and latency quantiles: executions, steps, dispatch outcomes, policy decisions, replay hits, and queue depth. |

## Sessions and subagent trees

**View tree** on an execution shows the [session](/architecture#sessions) it
belongs to: each turn in order, the [subagents](/architecture#subagents) it
started beneath it, and any session that branched from it.

## Reaching the kernel

The browser never calls the kernel. Every request goes to the dashboard's own
`/api/v0/*` route, which forwards it to `REBUNO_URL`. Without
[sign-in](#sign-in), it attaches `Authorization: Bearer $REBUNO_API_KEY`. No
token ever reaches the browser.

<Warning>
  Without sign-in, anyone who can reach the dashboard gets the access of
  `REBUNO_API_KEY`. Turn on sign-in or put the dashboard behind your own
  authentication before exposing it.
</Warning>

## Sign-in

Set `OIDC_ISSUER` and the dashboard signs users in with your identity provider
and calls the kernel as each of them. Register the dashboard as a web
application with the redirect URI `<DASHBOARD_URL>/auth/callback` and the
post-logout redirect URI `<DASHBOARD_URL>/`:

```bash
OIDC_ISSUER=https://corp.okta.com/oauth2/default
OIDC_CLIENT_ID=0oa1rebunodashboard
OIDC_CLIENT_SECRET=…
DASHBOARD_URL=https://rebuno.corp.com
SESSION_SECRET=$(openssl rand -base64 32)
```

The dashboard forwards the user's ID token, so set the kernel's
`REBUNO_OIDC_AUDIENCE` to the dashboard's client ID. See
[OIDC](/deployment#oidc). Executions the user creates record them in
`created_by`, their approvals record them in `decided_by`, and
[access roles](/deployment#access) limit what they see. `REBUNO_API_KEY` is
not sent with their requests. With `OIDC_FORWARD_TOKEN=access`, the dashboard
forwards the access token instead, for providers that issue JWT access tokens
with an audience the kernel accepts.

Tokens are kept in an encrypted, httpOnly cookie and refreshed before they
expire when the provider issues a refresh token. Without one, the user signs in
again when the token expires. Every replica needs the same `SESSION_SECRET`.
The kernel reads the user's groups from the token, so add the scope your
provider needs to include them, such as `groups` for Okta.

## Metrics

Set `PROMETHEUS_URL` and the metrics page queries Prometheus over a time range
you pick on the page.

With it unset the page scrapes the kernel's `/metrics` endpoint instead. Those
are one process's in-memory counters. They are cumulative since that replica
started, so no time range applies. Across replicas you see whichever one
answered. The page labels which source it used. With sign-in, every signed-in
user sees metrics for the whole deployment. Point a real Prometheus at the
kernel for anything beyond local development.

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `REBUNO_URL` | `http://localhost:8080` | Kernel base URL. |
| `REBUNO_API_KEY` | none | Bearer token for the kernel's client and admin routes without sign-in. Required against a kernel started with `rebuno server`. |
| `OIDC_ISSUER` | none | Identity provider issuer URL. Turns on [sign-in](#sign-in). |
| `OIDC_CLIENT_ID` | none | The dashboard's client ID. **Required** with `OIDC_ISSUER`. |
| `OIDC_CLIENT_SECRET` | none | Client secret. Omit for a public client. |
| `OIDC_SCOPES` | `openid email profile offline_access` | Scopes requested at sign-in. |
| `OIDC_FORWARD_TOKEN` | `id` | Token forwarded to the kernel: `id` or `access`. |
| `DASHBOARD_URL` | none | The dashboard's external URL, used for redirects. **Required** with `OIDC_ISSUER`. |
| `SESSION_SECRET` | none | At least 32 characters; encrypts the session cookie. **Required** with `OIDC_ISSUER`. |
| `PROMETHEUS_URL` | none | Prometheus base URL for the metrics page. |
| `PORT` | `3000` | Listen port. |
| `HOSTNAME` | `0.0.0.0` | Listen address. |

## Running it

```bash
pnpm install
pnpm dev
```

Needs Node 20.9 or later and a kernel to talk to. `rebuno dev` is enough for
local work. It runs with auth disabled, so it needs no `REBUNO_API_KEY`.

## Docker

The image is built from
[`deploy/Dockerfile`](https://github.com/rebuno/dashboard/blob/main/deploy/Dockerfile)
and published to `ghcr.io/rebuno/dashboard` on tagged releases. It serves a
standalone Next.js build on port 3000:

```bash
docker run -p 3000:3000 \
  -e REBUNO_URL="http://kernel:8080" \
  -e REBUNO_API_KEY="$REBUNO_BEARER_TOKEN" \
  ghcr.io/rebuno/dashboard:latest
```
